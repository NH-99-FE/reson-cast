# 视频生成任务与恢复

## 产品行为

标题、简介和封面继续在后台生成并自动保存。标题/简介生成前先保存目标字段，其他字段仍可编辑和保存。生成写回比较任务提交时的目标字段原值；相同则保存，否则标记 conflict，不覆盖其他页面的修改。文本冲突保留生成正文，可在编辑页展开查看，点击“采用到编辑框”后再由用户保存。

## 状态与职责

- `video_generation_jobs` 是业务状态来源，记录视频、作者、类型、Workflow ID、原值、结果和错误。
- `queued` 表示等待执行，投递失败或响应丢失时仍保留此状态；点击“重新提交”使用同一任务和 Workflow ID。
- `running` 由工作流开始执行时写入；`completed`、`conflict`、`failed` 为终态。迟到的失败回调不能覆盖终态。
- 同一视频、同一种生成类型最多有一个 queued/running 任务，由数据库部分唯一索引保证；不同字段可以同时生成。
- 工作流负责步骤执行和重试，不再用供应商日志、死信或浏览器存储推断业务状态。
- 查询接口按当前用户、视频和生成类型读取最新任务。跨页面、跨设备可恢复进度，sessionStorage 不再参与任务恢复。

文本写回和任务终态通过一条 PostgreSQL CTE 原子提交。任务行锁串行化重复回调；已经完成的任务重试直接返回已保存结果，不会再次更新内容，也不会把第一次成功误报为冲突。Neon HTTP 驱动无需交互式事务。封面替换同样原子写入任务终态和旧文件清理记录。

## 服务端结构

视频业务入口集中在 `src/modules/videos/server/services/`：

- `generation.ts`：提交、重投、查询和结束任务。
- `generation-workflow.ts`：文本生成步骤和 SDK 适配。
- `thumbnails.ts`：替换/还原封面及清理恢复。
- `update.ts`：普通编辑、可见性切换和播放权限撤销。
- `deletion.ts`：删除请求与外部资源清理。
- `access.ts`：读取和作者权限。

路由处理输入与身份，调用业务入口；Mux、UploadThing、AI 客户端工具保留在 `src/lib`。不引入通用任务框架或 Repository 层。

## 前端

`useGenerationTask` 共用于三种生成操作，仅管理恢复、提交、等待、暂停、同步和同步失败的交互阶段。React Query 负责服务端任务查询；活动任务每 2.5 秒查询，单次等待 5 分钟后停止自动查询，保留字段锁定，通过“继续查询”恢复。查询超时不表示任务失败。

`useTextGeneration` 负责表单适配：结束后重新读取视频，仅同步对应字段；其他字段编辑不变。如果任务来自另一页面且当前字段已有未保存编辑，则保留本地编辑。普通保存继续只提交脏字段，并保留请求期间继续输入的内容。

生成按钮与编辑框分别控制：首次查询任务状态或查询失败时，普通文本编辑和保存仍可用，生成按钮等待状态确认；确认存在活动任务后，目标字段保持锁定，包括轮询失败和暂停期间。查询失败停止自动轮询并提供手动重试。加载图标不代表字段锁定，暂停或错误时不持续转圈。首次发现历史终态任务会静默同步最新内容，只有本页提交或观察到活动状态的任务结束时才发完成通知。

封面任务完成后同步图片，投递失败也有重试入口。封面上传或还原不因旧文件清理暂时失败而报保存失败；页面单独显示待清理数量和“重试清理”。

## 数据库变更与部署

先应用 `scripts/sql/add-video-generation-jobs.sql`，再部署代码；也可通过项目现有 `pnpm db:push` 同步完整 schema。SQL 新增两张表、状态约束、活动任务唯一索引及查询索引，不修改现有视频内容。它要求此前的视频删除/播放权限相关字段已同步。

保留未携带 jobId 的旧工作流执行分支和旧步骤名，使部署前已投递的任务仍能写回。旧任务不会自动补入新任务表；其完成内容仍可在视频详情读取。新页面不再读取旧 sessionStorage 记录。新提交/进度接口采用任务对象契约，部署时刷新已打开的编辑页；如果不能接受旧页面短暂不兼容，应先排空旧任务并安排客户端刷新，再切换版本。

服务配置仍见 `.env.example`：DeepSeek 文本服务与独立生图服务各自配置，Mux 提供字幕，QStash 签名校验保留。

## 人工恢复

正常情况下在编辑页点击“重新提交”或“重试清理”。如果页面已不存在，例如账号删除后晚到的文件回调，可运行：

```sh
RUN_VIDEO_RECOVERY=1 pnpm exec tsx scripts/retry-video-work.ts
```

该命令读取本地 `.env`，实际重投最多 100 个 queued 任务、清理最多 100 个视频的待清理文件；可能调用外部服务，应在确认目标环境后运行。失败记录保留，命令返回非零退出码，可再次运行。当前不自动安装定时任务；需要无人值守恢复时，可由现有调度设施定期运行相同恢复逻辑。

running 任务由 Workflow 执行/重试；如果失败回调本身未能落库，先在 Upstash 控制台恢复失败回调，不直接创建另一个任务。应用不会因为等待时间长而擅自把正在执行的任务标成失败。

## 验证

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm exec playwright install chromium
pnpm test:ui
```

`pnpm test` 包含 PGlite 本地 PostgreSQL 实测：内容与任务原子提交、重复回调、冲突保留、活动任务唯一约束、封面清理意图回滚、晚到上传、真实业务入口投递失败恢复和播放权限撤销恢复。数据库传输替换为内存 PostgreSQL，外部服务模拟，不读取真实服务凭据。

`pnpm test:ui` 自动启动模拟服务页面、运行 Chromium 并返回退出码。覆盖真实 React 表单和查询库的脏字段保存、并行生成、同步失败、跨页面/账号恢复、暂停继续、投递重试、清理恢复等。需要手动查看时使用 `pnpm test:ui:serve`。

这些测试不能代替真实 Mux、QStash、AI、UploadThing 联调，也不模拟多连接 PostgreSQL 的所有并发调度。第三方已接受请求但应用尚未获得资源 ID 的中断，仍依赖该服务的幂等/回调能力及运维排查。
