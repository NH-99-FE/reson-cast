# 视频权限与删除

## 配置与发布

1. 将 `.env.example` 复制为 `.env` 并填写服务密钥；线上在 Vercel 配置相同变量。不要提交真实密钥。
2. 在 Mux 创建 signing key，填写 `MUX_SIGNING_KEY_ID` 和 `MUX_SIGNING_PRIVATE_KEY`（Mux 返回的 Base64 私钥）。
3. UploadThing 应用允许路由覆盖 ACL；视频封面上传必须使用 private ACL。
4. 填写 QStash 当前/下一签名密钥。所有工作流缺少验签配置时返回 503，不能直接用伪造 userId 调用。
5. 更新数据库：`pnpm db:push`；仅新增任务/清理表可执行 `scripts/sql/add-video-generation-jobs.sql`。新增视频删除时间、运行 ID、错误字段及 `mux_playback_id_to_revoke` 待撤销播放 ID 字段，不会自动清理已有资源。
6. 部署代码，确保 `UPSTASH_WORKFLOW_URL` 指向本部署且工作流 URL 不被 Vercel 预览保护拦截。保留原 Mux / Clerk / UploadThing 回调配置。

本次不提供旧媒体迁移或 public 播放兼容路径。旧 Mux public 播放 ID / UploadThing public 文件不会因部署代码自动撤销；用新上传的视频验收，已有公开资源需单独清理或另行迁移，不能把其私密性当作已经修复。

## 行为

- 新视频仅创建 signed 播放 ID。公开视频也通过应用签发令牌，私密视频只有作者可获取。令牌响应不缓存，账号变化时重建客户端查询缓存。
- 公开视频改私密先隐藏、停止签发，并记录待撤销的旧播放 ID，再同步撤销该 ID 并建立新 signed ID。失败保留待撤销记录，在工作台点击“重试撤销”或重新保存私密设置可重试；验证操作只同步媒体状态，待撤销期间会提示使用“重试撤销”，不会恢复旧 ID，Mux 回调也不能绕过待撤销状态。撤销完成前不能重新公开。并发重试只撤销记录的旧 ID，未写入数据库的竞争替换 ID 会清理。无需新增后台工作流。已经下载/缓冲的内容无法收回。
- 视频图片按用途分流，详见 [图片分发与缓存](./video-images.md)。私有封面通过 `/api/videos/:id/image/:kind` 鉴权后 307 跳转到 60 秒签名地址，响应 private/no-store。工作台的公开视频封面与前台复用相同的公开入口和缓存；公开自定义封面通过独立公开源图入口进入 Next 图片优化缓存，该入口只认当前公开版本，不接受作者身份兜底。公开 Mux 自动封面使用与播放 ID 版本绑定的固定地址，浏览器及 CDN 允许缓存 1 小时，应用在缓存未命中时校验公开视频并签名取图。Mux 动态预览仍经鉴权跳转；这些图片无需复制到 UploadThing。自定义和 AI 封面保留 private ACL 的源文件，不在上传端重复生成展示尺寸。
- 删除先保存删除标记与运行 ID，再投递工作流；发送失败保留错误和资源 ID。在工作台可重试。相同未失败任务使用相同运行 ID，重复投递由工作流去重。
- 工作流先取消未完成上传、清理 Mux，再清理图片，全部成功后删除数据库记录。404 视为资源已清理；其他失败保留记录重试。
- 自定义封面切换/还原与旧文件待清理记录在同一 SQL 中提交。清理失败保留 key，编辑页可“重试清理”；已完成清理记录保留为 tombstone，防止旧上传回调重新挂载已删除文件。清理记录不使用视频/用户级联外键，视频不存在后的晚到文件仍可通过恢复脚本清理。
- 删除期间晚到的 Mux / UploadThing 回调不会恢复记录，新文件会清理。Clerk 删除用户同样先隐藏其视频，再由工作流清理资源并删除用户。
- 用户删除工作流失败可从 Upstash 控制台重试；不删除数据库记录来绕过失败。

## 验收（测试服务账号）

- A 上传私密视频：A 可播放；游客和 B 的搜索、详情、图片、评论、点赞、收藏请求均不可访问。
- 发布后游客可播放；改私密后旧播放 ID 不再有效，B 的图片源入口请求返回 404，A 可正常播放和获取字幕。此前公开封面的 CDN 缓存不主动撤销，旧优化地址仍可能访问。
- 删除公开/私密视频后从公开列表消失；工作台显示清理状态，完成后消失；服务控制台确认视频与自定义封面已删除。
- 上传期间删除，模拟上传取消与 asset 创建竞争，再投递 created/ready 回调，不留下媒体资源。
- 模拟 Mux / UploadThing 失败，确认错误状态和重试入口，重试后清理完成。
- 工作台连续更换及还原封面时，使用已有 thumbnailKey 刷新图片和播放器封面，不新增封面版本字段。
- 自定义封面上传中删除视频，延迟回调不恢复数据且清理其新文件；标题/简介生成中删除视频，工作流不得恢复或更新已删除的视频。
- 不带合法 QStash / Mux 签名的回调不可修改或删除视频。

本地自动测试覆盖权限查询条件与清理重试、上传竞争和工作流配置保护。真实 CDN 撤销与第三方回调必须使用配置齐全的测试环境联调。

运行数据库接口回归：`RUN_DATABASE_TESTS=1 pnpm exec tsx scripts/verify-video-access.ts`。它创建两名临时数据库用户和一条私密视频，验证游客/其他账号拒绝访问，并在 finally 中级联清理测试记录；不会创建 Clerk 用户或 Mux 媒体。只应在允许创建测试记录的环境运行。

## 首页查询缺少待撤销字段

如果首页 `videos.getMany` 返回 500，数据库已有删除相关字段，但尚无 `mux_playback_id_to_revoke`，需补齐播放权限撤销字段。可执行 `scripts/sql/add-video-playback-revocation.sql` 中的增量 SQL；它仅添加可空 text 字段，可重复执行，现有记录默认 NULL。应在部署读取该字段的代码前应用数据库变更。其他数据库仍需分别同步。
